5. Consideraciones para los Identificadores No Válidos

En tu parser, si después de procesar flags, width y precisión, el carácter no es un conversor válido:

    Opción A (Sencilla): Tu parser se detiene y tú imprimes el % y regresas al bucle principal desde el carácter siguiente al %.

    Opción B (Fiel al original): El printf original a veces imprime la secuencia fallida completa. Para 42, lo más común es que si el identificador es inválido, 
	el comportamiento es "undefined", pero imprimir el % y el carácter actual suele ser lo que esperan las pruebas.

Diferencias clave que verás en los tests:

    %p: Siempre imprime 0x al principio. Si el puntero es NULL, depende del SO (puede ser (nil) o 0x0).

    %.0d con valor 0: ¡No debe imprimir nada! (La precisión 0 anula el número 0).

    Flag #: Solo añade 0x o 0X si el número no es cero.

 (Spoiler: La precisión siempre gana y desactiva el 0).

 El comportamiento de la precisión 0 es, probablemente, la parte más "caprichosa" de todo el proyecto ft_printf. Depende totalmente del tipo de conversor que estés usando.

Aquí tienes el desglose de cómo reacciona el printf original cuando le pasas %.0 o %.:
1. Números Enteros (%d, %i, %u, %x, %X)

Este es el caso que hace fallar a la mayoría en 42.

    Si el valor es 0: printf("%.0d", 0) no imprime absolutamente nada. Ni siquiera el cero. El retorno de la función será 0.

    Si el valor NO es 0: La precisión 0 se ignora. printf("%.0d", 42) imprime 42.

    Si hay Width: printf("%5.0d", 0) imprimirá 5 espacios en blanco. El "hueco" del número queda vacío porque la precisión 0 anuló al valor 0.

2. Strings (%s)

Para los strings, la precisión indica el máximo de caracteres a imprimir.

    printf("%.0s", "Hola"): No imprime nada.

    Básicamente, cualquier precisión 0 con un string resulta en una cadena vacía, ya que le estás diciendo: "imprime como máximo 0 caracteres".

3. Punteros (%p)

Aquí la cosa se pone interesante y depende del sistema operativo (Linux vs macOS), pero para el estándar general:

    En la mayoría de implementaciones modernas, la precisión en %p se ignora o se comporta como en los enteros.

    Caso crítico 42: Si haces printf("%.0p", NULL), algunas versiones imprimen 0x y otras nada tras el 0x. Sin embargo, el subject de 42 suele ser más flexible con los punteros. Lo más seguro es tratar el puntero como un número hexadecimal de cara a la precisión.

4. Caracteres (%c) y Porcentaje (%%)

    Se ignora completamente.

    printf("%.0c", 'A') imprimirá A. La precisión no tiene sentido para un solo carácter.

Un detalle sobre los flags # y 0

    Con %#x: Si el valor es 0 y la precisión es 0, el flag # no añade el 0x porque el valor es cero. No se imprime nada.

    Con el flag 0 (relleno de ceros): Si hay una precisión (aunque sea 0), el flag 0 se desactiva en los números. Solo se usarán espacios para rellenar el width.
